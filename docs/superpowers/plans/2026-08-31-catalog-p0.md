# Catalog P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Working nav categories on the real store, every listed product tagged/typed/slugged into one of them with CJ US stock as tracked Shopify inventory (kept fresh by a 6-hourly sync), and sourcing knobs that let a catalog-build week produce ~40 products.

**Architecture:** One source of truth for categories in `packages/core` (`CATEGORIES`, typed against the existing `CATEGORY_TAGS` enum) consumed by the storefront nav, a new idempotent `seed-collections` script (create + publish to every publication), the listing worker (tags/type/seo/slug handle/tracked inventory + inventory-item gid), a `backfill-listings` repair script, an `inventory.sync` pg-boss job (cron + on-demand), and settings/CLI overrides for the sourcing pipeline's caps.

**Tech Stack:** TypeScript (Node 22, ESM `.ts` imports), drizzle-orm/Postgres, pg-boss, zod, vitest (real local DB on 5433), Shopify Admin GraphQL 2026-07 via `packages/shopify-admin`, CJ via `packages/supplier`, Hydrogen storefront.

**Spec:** `docs/superpowers/specs/2026-08-31-catalog-p0-design.md` — read it first; every task cites its sections.

## Global Constraints

- Run everything from the repo/worktree root with `pnpm --filter @doge-buddy/<pkg> …`. `apps/ops` `test` is vitest-only; CI gates on a separate `pnpm typecheck` — run BOTH before calling a task green. Local DB: `postgres://doge:doge@localhost:5433/doge_buddy` (shared container from the main checkout — never `pnpm db:up` in a worktree). No new migration is expected; if one becomes necessary it MUST be generated with `pnpm --filter @doge-buddy/db generate` and listed on OWNER-CHECKLIST as "migrate Railway FIRST, then push".
- Category truth: `CATEGORY_TAGS = ['toys','walks','beds','grooming']` (existing). Shopify tag value = `category:<tag>`. Collection handles/titles/productTypes exactly as spec §1's `CATEGORIES` table. Nothing may hardcode a category outside `packages/core/src/catalog.ts`.
- Handle = `${slugify(title)}-${proposalId.slice(0, 8)}`; `slugify`: NFKD-normalize, strip diacritics, lower-case, replace every run of non `[a-z0-9]` with `-`, trim leading/trailing `-`, cap the slug part at 60 chars (then trim `-` again). Empty slug → `product`.
- Inventory: quantity = sum of `WarehouseStock.quantity` over entries with `countryCode === 'US'`, clamped to `>= 0`; a failed stock read at listing time yields quantity 0 and a listed product (never a blocked listing). `inventorySetQuantities` input: `{ name: 'available', reason: 'correction', ignoreCompareQuantity: true, quantities: [{ inventoryItemId, locationId, quantity }] }` with idempotency key `inv-<variantRowId>-<UTC yyyymmddHH>` (chars limited to `[A-Za-z0-9_-]{1,64}` — see `IDEMPOTENCY_KEY_PATTERN`).
- Sourcing defaults unchanged: winners 3, candidates 15, pages 10, budget $2.00 (`200` cents). Precedence: CLI override > `settings` row > constant. `--keywords` caps at 8 entries, each trimmed, non-empty.
- Every live Shopify/CJ call shape that is new to this branch (`productSet` returning `inventoryItem { id }`, `productUpdate`, `locations` query, `inventoryQuantities` on ProductSetInput, `collectionCreate` with `descriptionHtml`, `publishablePublish` on a Collection) is a FIXTURE-ASSUMPTION until the credential-gated live step verifies it — say so in a comment at each site, like the codebase already does.

```ts
import { CATEGORY_TAGS, type CategoryTag } from './proposals.ts'

export interface CategoryDef {
  tag: CategoryTag
  /** Storefront collection handle — also the header nav route `/collections/<handle>`. */
  handle: string
  title: string
  /** Shopify `productType` stamped on every product listed in this category. */
  productType: string
  /** One-line collection description. */
  blurb: string
}

/**
 * The single source of truth for the store's categories (spec 2026-08-31 catalog-p0 §1). The
 * proposal schema's `CATEGORY_TAGS` enum fixes WHICH categories exist; this table fixes what each
 * one looks like on the store. The `satisfies` + the consistency test keep the two aligned.
 */
export const CATEGORIES = [
  { tag: 'toys', handle: 'toys-play', title: 'Toys & Play', productType: 'Dog Toys', blurb: 'Tug, chew, fetch, puzzle — gear that keeps the tail going.' },
  { tag: 'walks', handle: 'walks-travel', title: 'Walks & Travel', productType: 'Dog Walking', blurb: 'Leashes, harnesses, bowls and carriers for the road.' },
  { tag: 'beds', handle: 'beds-comfort', title: 'Beds & Comfort', productType: 'Dog Beds', blurb: 'Beds, blankets and calming spots for the off hours.' },
  { tag: 'grooming', handle: 'grooming-care', title: 'Grooming & Care', productType: 'Dog Grooming', blurb: 'Brushes, clippers and care tools for at-home upkeep.' },
] as const satisfies readonly CategoryDef[]

export function categoryByTag(tag: CategoryTag): CategoryDef {
  const found = CATEGORIES.find((c) => c.tag === tag)
  if (!found) throw new Error(`unknown category tag ${tag}`)
  return found
}

/** The Shopify product tag the automated collections key on. */
export function categoryTagValue(tag: CategoryTag): string {
  return `category:${tag}`
}

const SLUG_MAX = 60

/** URL slug: ASCII, lower-case, `-` separated, ≤ 60 chars, never empty (`product`). */
export function slugify(input: string): string {
  const ascii = input
    .normalize('NFKD')
    .replace(/[̀-ͯ]/g, '')
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '')
  const capped = ascii.slice(0, SLUG_MAX).replace(/^-+|-+$/g, '')
  return capped.length > 0 ? capped : 'product'
}

export { CATEGORY_TAGS }
```

```ts
export async function primaryLocationId(client: ShopifyAdminClient): Promise<string> {
  const data = await client.graphql<{ locations: { nodes: { id: string }[] } }>(PRIMARY_LOCATION_QUERY)
```
